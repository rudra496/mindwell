# MindWell UI & Layout Rules

These rules were learned from debugging mobile responsive layouts in the MindWell project.

1. **Shadcn Button Mapping & Text Wrapping**: When mapping lists of items (like assessments, games, or conditions) into Shadcn `Button` components to act as cards, you **must** explicitly override the Shadcn default by appending `whitespace-normal` to the `className`. Otherwise, Shadcn's default `whitespace-nowrap` will override `line-clamp` or `break-words` on child text elements and cause text to bleed out of the box on mobile.
2. **CSS Grid Shrinking Constraints (`min-w-0`)**: When rendering long, unbreakable text strings (like email addresses or URLs) or long paragraphs inside a CSS Grid column, the grid item calculates its minimum width based on the intrinsic `min-content` of that text. This prevents the grid from scaling down on mobile devices and pushes content out of bounds. To fix this, always apply `min-w-0` to grid children containing text, which allows them to shrink below their intrinsic size, and apply `break-words` or `break-all` to the text elements.
3. **TabsList Overflow**: When using Shadcn `TabsList` on mobile screens, the default `whitespace-nowrap` will cause horizontal overflow that can stretch the parent `DialogContent` container beyond `95vw`. To fix this, change the `TabsList` classes to use `flex-wrap h-auto` and ensure the parent `Tabs` wrapper has `min-w-0` so the tabs gracefully stack or wrap instead of breaking the layout.
4. **DialogContent Bounds**: Always explicitly apply `break-words whitespace-normal overflow-x-hidden` to `DialogContent` components in mobile views to act as a fail-safe against horizontal layout bleed. Ensure that you do not accidentally append a trailing slash (e.g. `\"`) inside the JSX `className` string.
5. **Canvas Touch Events**: When implementing games (like ThoughtSlicer) using HTML5 `<canvas>`, always map `onTouchStart`, `onTouchMove`, and `onTouchEnd` to handle `e.touches[0].clientX` with standard bounding rect calculations to ensure full Android/mobile playability, rather than relying exclusively on mouse events.
6. **WebGL / Three.js Resize Observers**: When mounting Three.js canvases inside responsive containers (like LogicRivers3D), always use a `ResizeObserver` attached to the wrapper div to dynamically update `camera.aspect = width / height` and `renderer.setSize(width, height)`. Do not use static sizes (like 400px width/height) if you want it to look good on mobile.
